# Codebase audit and isolated load test - 2026-09-05

Historical review-stage report, not a guarantee about the latest checkout.
The [follow-up](explorer-storage-2026-09-05.md) records subsequent changes and
remaining overload failures. Referenced `/tmp` artifacts are author-local evidence,
not files distributed with this repository. Current setup/check commands live in
[CONTRIBUTING.md](../CONTRIBUTING.md).

This review covered first-party server, transport, scheduler, metrics, storage,
configuration, dashboard, tests, and development tooling. It is not a proof that
the application is bug-free. Existing changes were preserved; the workspace is
not a Git checkout. Readers worked in parallel, with one repository writer at a
time. Reproductions used local fixtures, temporary databases, and the isolated
development instance. The main instance on port 8080 was not restarted or loaded.
No requests were sent to paid providers.

## Correctness and safety changes

| Area | Reproduced problem | Shared fix / regression coverage |
| --- | --- | --- |
| Settings | Blank allowlist entries could disappear before validation; invalid listen addresses and fractional integer YAML could survive loading. | Validate explicit values before merging, use the existing schema's integer kinds, reject invalid addresses before persistence. Tests in `internal/config`. |
| Restart | A drain timeout or flush failure could still proceed to a child; failed recovery retained a closed listener; progress could outlive a panic. | One handoff fence requires successful drain and flush. Abort and resume on failure, retain active retired servers in later drain fences, atomically finish failures, stop/join progress reporting. Tests in `cmd/proxy/restart_test.go`. |
| Development tooling | Overrides could target unsafe ports/files; raw SQLite copying missed committed WAL contents. | Loopback/non-production port and scratch-path validation, exact PID-file identity, read-only SQLite backup into a new file. `cmd/proxy/dev_test.go`. |
| Operator/browser boundary | Foreign browser mutations and hostile provider labels could reach unsafe surfaces. | Cross-origin protection on operator mutations only, delegated operator controls, escaped labels, HTML `frame-ancestors 'none'`. Inference remains uncompressed and outside operator-origin policy. |
| Upstream transport | Redirect following could leave the allowed destination; HTTP/2 TLS selection depended on port rather than scheme. | Do not follow redirects; preserve their status, body, and Location. Separate HTTPS/TLS and HTTP/h2c transports by scheme. Local-only transport regression fixtures. |
| Header authority | Invalid or duplicate injected header names produced late or nondeterministic behavior. | One token/case-fold uniqueness validator, strict duplicate-aware JSON object decoding, and removal of Connection-nominated hop headers. |
| Retained credentials | Response headers and custom authentication headers could enter ordinary metrics or opt-in debug capture. | Shared capture-only redaction without changing the forwarded wire response. Tests cover configured auth, injected headers, Set-Cookie, and retained metadata. |
| Continuation lifecycle | Active upstream work survived client cancellation; parked tool calls could collide across identities or expire only on later traffic. | Shared context-aware turn lifetime, complete route/auth/model/client scope, atomic duplicate denial, identity-checked index removal, and one configured TTL timer. |
| Metrics | Legal numeric values could overflow derived arithmetic; fractional counts were truncated; percentile consumers could diverge. | Shared checked count/value sums, representable scaled ratios, strict count extraction, shared R7 chart/explorer percentiles, and corrected nearest-rank Prometheus/stress percentiles. Unrepresentable ratios become unavailable/null; unrepresentable aggregate sums fail explicitly rather than emitting invalid JSON. |
| Live feed | Subscriber overflow could permanently skip records; observer model/time interpretations could diverge from server aggregates. | Retire only overflowing subscribers so replay/resync recovers; server-owned model revision/name dictionaries and time buckets on observer envelopes, with client revision barriers and bounded pruning. |
| Durable accounting | KPI reads could count a batch inconsistently across its commit boundary; explicit zero/false request parameters disappeared after restart. | Atomic durable-plus-unwritten totals; one durable presence-bit mapping for request parameters. Tests cover commit races, restart, migration, and export. |

| Operator persistence | Debug and Limits concealed save failures; concurrent partial Debug edits could restore stale fields. | One successful-applied-state warning response across Pause/Debug/Limits; atomic Debug read/merge/check/commit; latest-generation persistence outcomes. Header-applied limits still do not fail an inference request because a save failed. |
| Chart consistency | Optimistic browser arithmetic duplicated authoritative aggregate behavior. | Remove optimistic bucket overlays; use server buckets at the existing configurable refresh cadence. Request rows and in-flight gauges remain event-live. |
| Operator menu interaction | Editing or resuming a row detached the click target before the outside-click listener ran, closing the menu. | The shared outside-click owner checks the stable dispatch path. Shared duration precision and axis-label uniqueness preserve units. |
| Stream and format accounting | Legal JSON spacing/escapes were missed; terminal usage could borrow overwritten bytes; translated usage/cost and tool identity were inconsistent. | Shared lexical key lookup and terminal detection, owned usage bytes, one native cache-inclusive usage converter, one-time tool identities/contiguous indices, original-source custom cost observed privately and joined before finalization. |
| Token range and quotas | Proto narrowing and count addition could wrap; invalid totals could refund a reservation. | Validate proto values and accumulated counts, share checked wire/record usage, report `invalid_usage`, and retain the original reservation while releasing concurrency exactly once. | Conversation retention | Per-partition ID counters survived idle partition reclamation indefinitely. | One process-lifetime sequence preserves fresh IDs without retaining historical partition counters. |

The chart still offers all history and longer ranges, speed plus latency, one
percentile control, unit-correct money formatting, and persisted view controls.
Bootstrap data is embedded in the initial HTML; the browser does not need a
second bootstrap request before its first data render. Chart/explorer scans run
separately. Restart controls stay disabled while a restart is in progress;
unchanged assets preserve the document, while changed assets reload it and keep
the saved view.

Real Chromium checks with a small 16-record fixture measured KPI/log DOM arrival
at 51 ms on a fresh load and 28/19 ms on repeat loads; chart arrival was 85/50/30
ms. First contentful paint was 44/32/20 ms. There was no separate bootstrap fetch,
only one chart and one explorer request, and repeat assets revalidated without
body bytes. These are local fixture measurements, not a large-history or remote
network guarantee. All nine time ranges, saved All view, scoped footer, mobile
overflow checks, and speed/latency percentile changes passed. Real Pause queue,
edit/resume, Settings save/revert/conflict/draft, zero/false export, scoped purge,
and second-tab automatic refresh checks passed without browser errors.

Final-source Chromium verification also passed all six actual-canvas combinations
(desktop/mobile × p50/p95/p99), requiring visible pixels from both independently
scaled singleton series. An actual development rebuild/restart preserved the
document and saved view when asset hashes matched; simulated changed-asset
notifications through both SSE and polling reloaded once and preserved the view.
The reusable `scripts/browser_check.py` adds the chart regression, and
`scripts/browser_check_test.py` checks its private-target/database and redirect
isolation even under Python `-O`. This chart-only fixture deliberately disables
SSE and exercises bootstrap/poll rendering; the separate lifecycle and restart
checks cover live behavior.

A separate final-source load with 33,075 durable requests (480 bootstrap rows)
measured cold-load KPI/log DOM arrival at 83 ms, first contentful paint at 156 ms,
and chart arrival at 239 ms. The first repeat load measured 44 ms, 68 ms, and
70 ms respectively. A third navigation did not expose a paint entry and is not
used as an independent paint measurement. The cold chart/explorer requests each
took about 159 ms; repeat requests took about 3 ms. All nine ranges, saved All
view, scoped footer, and mobile overflow checks still passed. This larger fixture
shows why sub-120-ms first chart paint is not a universal guarantee, despite
embedded bootstrap and cached aggregate reuse. Evidence:
`/tmp/millivolt-final-boot-large.jsonl`.

`storage_query_max_bytes` and `storage_query_max_rows` are startup-bound settings
owned by `Config`, with defaults only in `config.Default()`. Their types, ranges,
defaults, and reload behavior are documented in `proxy.yaml` and exposed through
the existing Settings schema. No benchmark tuning was applied to the main config.

Model discovery adds `models_discovery_timeout` (default 30 seconds),
`models_discovery_max_bytes` (8 MiB), and `models_discovery_max_pages` (100).
Limits apply to new discoveries after hot reload. The time budget includes key
refresh; byte/page budgets count model responses and enrichment, while refresh
retains its separate existing bounded reader. These are configurable safety
guardrails, not measured catalog requirements or strict process-heap caps.

The compact SSE benchmark improved from approximately 890 to 416 ns/event with
zero allocations. A newly introduced per-line JSON-validity check was removed
after it incorrectly rejected valid multi-line content. Its byte-preservation
regression and exact zero-allocation check pass in normal and race tests; no
race-only exemption remains. This does not claim full SSE event conformance.

## Stress test method

The reusable `cmd/stress` harness targets only an explicitly selected, verified
`scripts/dev.sh` instance. It does not start, stop, or reconfigure a proxy.
It creates a local synthetic HTTP/1.1 upstream and uses closed-loop client
workers. Each response lasts one second and contains ten content frames, a
terminal usage/cost frame, and `[DONE]`. The fixture reports 100 input tokens,
10 output tokens, and $0.001 synthetic cost. These values test accounting and
are not provider charges.

The harness checks exact response bytes and durable request/input/output/cost
totals. It distinguishes attempts, successful responses, failures, and accepted
upstream requests. A client connection failure is not labeled as a lost database
write. On failure it stops starting work and drains already accepted work. It
samples proxy and generator CPU, RSS, and file descriptors, checks an initial RSS
safety budget, and reuses client connection pools between ramp stages. Output
includes only allowlisted performance settings, never the complete configuration.

Environment: Linux amd64 VM, Go 1.26.6, 12 reported CPUs, Intel Core Ultra 9 285H,
approximately 72 GiB RAM. Proxy, mock upstream, and generator share the machine.
CPU 100% means one logical core; RSS is sampled, not an absolute transient maximum.

closed-loop stages:

| 1 | 1 | 0.99 | 1012 ms | 21.7 MiB | 0.33% |
| 8 | 8 | 7.92 | 1011 ms | 22.7 MiB | 1.32% |
| 32 | 32 | 31.07 | 1066 ms | 24.9 MiB | 4.21% |
| 128 | 128 | 122.05 | 1060 ms | 36.1 MiB | 13.67% |

All stages had zero response failures and exact durable row/token/cost counts. The
1024-worker latency increase is consistent with queuing behind the configured

| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |

Both stages had zero failures, exact bytes, and exact durable input/output/cost

A separate 2048-worker run with one real Chromium dashboard open completed
10,240 requests with exact bytes and accounting (about 1870 requests/sec). The
browser temporarily fell back to polling during burst-driven SSE disconnects,
then reconnected automatically within the 30-second test deadline. Final state
was live with correct global totals, zero in-flight/stale pending rows, and no

### Fast responses expose a separate durability ceiling

With the same expanded development pool, ten frames but no artificial upstream
delay, and three-second stages:

| Client workers | Successful HTTP requests/sec | p95 total | Durable rows / HTTP successes | Result |
| ---: | ---: | ---: | ---: | --- |
| 1 | 1474.85 | 1.05 ms | 4425 / 4425 | Exact bytes and accounting |
| 32 | 9310.07 | 7.14 ms | 27954 / 27954 | Exact bytes and accounting |
| 128 | 16779.72 | 14.43 ms | 25861 / 50430 | Durable accounting failed; ramp stopped |

The final stage had zero HTTP failures but a 24,569-record durable shortfall
(48.7%). It remained after shutdown drained the writer, verified against the
stopped private database. No batch-insert errors were present in the dev log;
this is consistent with the intentionally nonblocking queue overflowing. The
harness did not capture a before/after `storage.dropped` delta, so it cannot
numerically attribute each missing row to that counter. Its nonzero exit status
correctly treats this as a failed stage, not a clean 16.8k-request/sec result.

The existing queue capacity was 8192, batch capacity 256, and flush interval
500 ms. These are configurable, but raising a queue only absorbs a longer burst;
it does not establish sustainable writer throughput. No production storage
settings were changed. This test establishes separate request-serving and
durable-accounting boundaries; it does not measure the exact sustained storage
ceiling. Raw output: `/tmp/millivolt-final-stress-fast.jsonl`.
All three storage knobs require restart. Larger batches may amortize transaction
cost, but need a separate measurement; shortening the partial-batch flush interval
does not address saturation when batches already fill immediately.

### Why no reliable higher ceiling is claimed

The host has only 4096 ephemeral ports in its configured range. A 4096-client
single-source attempt encountered local dial exhaustion. Experiments with four
local source addresses and four mock destinations then suffered delays before
recorded proxy work and client timeouts, despite low recorded proxy CPU and
roughly one-second completed upstream durations. Even localhost is routed through
this environment's virtual gateway rather than an ordinary local route. Source
separation and a temporary per-socket port-allocation experiment did not produce
a valid higher-capacity measurement. No network routes or sysctls were modified,
and the socket experiment was not installed in the application. The 8192-client
stage was not reached.

This is a short closed-loop throughput/concurrency test, not an endurance test,
an open-arrival overload test, an HTTP/2 capacity test, a many-observer test, or
a provider-network benchmark. Closed-loop workers stop offering additional load
while responses slow; see [Grafana's workload model explanation](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/).

## Remaining limitations and follow-up evidence

- Asynchronous metrics storage remains best-effort: a full write queue or failed
  batch can lose durable records. Bootstrap `storage.dropped` exposes cumulative
  process-local drops. Zero loss in successful stages is not an unconditional
  lossless-persistence guarantee; the fast-response overload stage above exposed
  this boundary.
- Non-streaming metric inspection retains a fixed bounded prefix (1 MiB),
  not a JSON tail. Larger responses are forwarded in full, but complete JSON
  accounting may be unavailable. Changing the prefix to a tail or lifting the
  cap does not solve bounded structural parsing. A future selected-field parser
  needs key/scalar/depth/node bounds, full-document validity checks, fuzzing, and
  memory benchmarks before replacing this path.
- General multi-line SSE event accounting and native-adapter event assembly are
  incomplete. Some split key/value or terminal shapes can still be misclassified,
  not merely lose metrics. The specific newly introduced multi-line-content wire
  regression was repaired; a complete event decoder/terminal-hold redesign needs
  separate compatibility and buffering review. Non-streaming format translation
  also still buffers the complete response; discovery budgets do not cap it.
- SQL response and scalar/row-size bounds do not strictly cap every SQLite
  intermediate sort or aggregate allocation. This remains an operator endpoint,
  not a sandbox for untrusted SQL workloads.
- Arbitrary concurrent processes writing the same metrics database are not a
  supported KPI-accounting deployment. The supported restart path drains and
  flushes before handoff instead of relying on overlapping writers.
- Historical zero/false request values already discarded by an older version
  cannot be reconstructed by migration.
- Extreme finite provider values can make an aggregate unrepresentable. The
  service reports an encoding/accounting error rather than fabricating saturated
  or capped prices; correcting bad historical data is still an operator task.
- Scheduler group reclamation and intentional historical identity sets warrant a
  separate long-running cardinality test. These are reviewed follow-ups, not
  measured exhaustion claims. The model-discovery read/deadline/pagination gaps
  identified during this review have been fixed and tested with small fixtures.
- Cross-origin checks and framing protection are not authentication. Keep the
  dashboard, SQL, debug, settings, purge, and restart routes on a trusted operator
  network. Configure allowed destinations when inference clients are not trusted.

## Reproduction and authoritative references

Use `scripts/dev.sh`, then `go run ./cmd/stress -target http://127.0.0.1:8081`;
stop with `scripts/dev.sh stop`. For code checks run `go test ./... -count=1`,
`go test -race ./... -count=1`, `go vet ./...`, `go build ./...`, and
`node ui_check.js`. All passed on the final source: 11 Go packages in normal and
race mode, vet/build, and 480 UI assertions. A clock-dependent canonical-scope test
was reproduced deterministically with older records and corrected to sum the
whole requested chart window, rather than incorrectly asserting only its newest
bucket. Temporary browser fixtures also exercise real queued Pause
requests, Settings conflicts, zero/false export, filtered purge propagation,
restart asset identity, long chart ranges, and responsive layout.

The strict JSON boundary fuzz target completed 1,041,589 generated cases in a
15-second fuzz window without a failure. The request string-size parser completed
129,191 generated cases in a separate 15-second fuzz window without a failure.
Operator persistence regressions cover
all three controls, rejected edits versus applied-but-unsaved state, stale save
generations, no-store mode, exact omitted deadlines, and concurrent disjoint
Debug edits without sleeps or probabilistic scheduling.
