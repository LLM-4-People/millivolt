# GitHub readiness - 2026-09-05

Three passes used parallel readers and one repository writer at a time:
inventory/research, implementation with cross-review, and independent publication
and clean-source verification. This dated report describes the earlier local
source-preparation stage, before versioning, containers or hosted publication.
That stage did not create a hosted repository, commit, push, release or
deployment. Statements below describe that point in time; the current
[operations guide](operations.md#versions-and-images) owns release/image usage.

## Publication and documentation

- Added the user-selected MIT license and uPlot's complete versioned notice.
  [Third-party notices](../THIRD_PARTY_NOTICES.md) distinguish source preparation
  from the additional review needed for binary distribution.
- Reduced README to a safe quickstart and navigation. Replaced the oversized
  agent notebook with focused working rules and linked protocol, operations,
  architecture and adapter guides. Dated performance reports remain historical
  evidence, including failed stages and local-only artifact limitations.
- Public `proxy.example.yaml` is generated through `-print-config`, using the
  existing default/schema/YAML owner. The full generated bytes are tested;
  private local `proxy.yaml` is no longer an implicit fixture or dev input.
  `DEV_CONFIG` is an explicit opt-in, copied with private permissions.
- Added read-only, commit-pinned CI, weekly dependency-update configuration,
  contribution/issue guidance and one shared local/CI check command. Runtime
  versions live in their version files, not a second workflow version table.
- Added offline Markdown-target and real-Git ignore checks, with deterministic
  regressions for missing links, hidden command source and inherited Git routing
  variables. Checks work without an existing Git checkout.
- Excluded local settings, credentials, databases/sidecars, binaries, caches,
  captures, exports and test artifacts. Four unrelated research downloads were
  moved to a recoverable author-local directory outside the publication set.
  The live database, local config and existing main binary were not changed.

The publication directory now has a local `main` branch with untracked source;
no initial commit or remote was configured. Review and commit the intended files
before pushing. Do not upload a whole-workspace archive: ignored runtime data
still exists locally. Configure hosting access, push protection and a private
vulnerability-reporting channel deliberately; this work did not enable them.

## Reproduced corrections

The metrics SSE handler unnecessarily opted into cross-origin browser reads.
That permission was removed at its existing owner. Same-origin EventSource and
direct API replay still work; this is not authentication. A four-origin replay
regression failed before the change and passed afterward. The behavior follows
the [EventSource CORS contract](https://html.spec.whatwg.org/multipage/server-sent-events.html#the-eventsource-interface).

Login helper failures could print response bodies containing credentials.
Error messages now withhold those bodies and arbitrary upstream error strings;
success output remains intentionally credential-bearing and is documented as
private. Three deterministic fake-tool cases reproduced the leakage before the
fix and passed afterward; no real account login was performed.

Cross-review also corrected curl's present-empty auth-header example, provider
header/template documentation and path-specific precedence, shared concurrency
scope, distinct percentile contracts, YAML end-of-file formatting and the PR
template's context-dependent relative link. Provider mappings from mutable local
config were not promoted to public defaults.

## Verification

The source-only export was assembled from the reviewed Git publication set,
without local config/database/binary or installed dependencies. It received a
fresh `npm ci --ignore-scripts` and used Go 1.26.6, Node 24.20.0 and Python 3.13.15
with the pinned browser dependencies. The shared core command passed twice,
including after the final source cleanup:

- Formatting, shell syntax, offline publication checks, module verification,
  build and vet; all 11 Go packages normally and under the race detector.
- All 544 jsdom checks and four publication-checker self-tests.
- Workflow validation with actionlint 1.7.12. Optional ShellCheck/Pyflakes were
  unavailable; this is not a hosted GitHub Actions execution.
- Source-only staged whitespace validation. The actual workspace index remains
  unstaged; staging for this check occurred only in the disposable export.

Real Chromium fixtures passed desktop/mobile chart rendering at p50/p95/p99,
all nine explorer dimensions, hidden zero health badges, lineage summaries and
exact parent pivots, with no overflow or browser errors. These fixtures disable
SSE; a separate actual-page check confirmed same-origin EventSource opens with
no CORS permission header. Only a private dev instance was used and it was stopped.

A small clean-export stress smoke used one-second synthetic streams with
1, 8 and 32 workers. All 41 successful responses had exact bytes and durable
accounting, with zero storage drops. This checks reproducibility, not capacity.
The [sustained overload failure](explorer-storage-2026-09-05.md#remaining-capacity-failure)
remains unresolved; no queue enlargement or durability weakening was applied.

Govulncheck and npm audit reported no known vulnerabilities. Version-specific
OSV/PyPI checks found no listed advisories for the reviewed dependencies/uPlot.
These are advisory checks, not a security proof or exhaustive browser-binary audit.
Source scans found no obvious credentials or personal home paths; private runtime
contents and nonexistent pre-initialization Git history were not scanned.

## Remaining boundaries

The service still requires a trusted operator/network and has no built-in
operator authentication. Storage remains best-effort under sustained overload.
An existing private context-length mapping pointed at a model-version field;
it was excluded from publication and left for deliberate operator correction,
not silently edited or reloaded during repository preparation.
